## 任務與範圍

在使用者於 Figma 端指定的三個目標檔案中，建立下表的 Pages、Sections 與**空白** Frame placeholders。角色／檔案名稱為「客戶端」、「師傅端」、「App 管理員」。三檔合計 23 個 Pages（14 個功能 Page、9 個固定輔助 Page）、71 個 Sections、272 個 Frames（2026-10-07 師傅端調整：新增 2.4.1、2.6.1、2.6.2、2.3.3，原 2.4.1 至 2.4.11 順移為 2.4.2 至 2.4.12，原 2.6.1 上傳畫面順移為 2.6.3，原 2.6.2 刪除確認與 2.6.3 上傳失敗改沿用 2.3.3、2.3.2 不另建，合計仍為 272）。客戶端 9／41／179；師傅端 9／24／80；App 管理員 5／6／13（Page／Section／Frame）。71 個 Section 各有至少一格。

接手者先向使用者取得各角色的 Figma 目標檔案或由使用者指定的新建目標與名稱，核對本包版本 r01。沒有指定目標的角色暫停該檔批次，不自行挑選檔案。未列出的既有內容不更動。只建立架構占位；不填 UI、不套元件、不猜新畫面、不畫完整流程圖、不作 prototype、不修改 App。

## Placeholder 規則

- 所有 272 個 Frame 都是 393×852 的空白占位，包括 Dialog、Bottom Sheet、Action Sheet 與已確認的外部／系統邊界位置；不使用 375×812。邊界占位只標明去向，不描繪商店、權限、通知或網站內容。
- 每個 Frame 內僅放「尚未填入畫面」、本表的類型與一句情境說明；不放畫面元件、假資料、Flutter 路徑、Widget 名稱或程式標註。占位不代表 UI 已設計、現行 App 已實測。
- 名稱為「位置編號＋一個空格＋名稱」，與完整結構表完全相同；Page、Section、Frame 僅三層，不加第四層或永久 ID。固定輔助 Page 只用表列英文名稱。
- 在每個功能 Page 中，Sections 依數字由上到下排列，Section 間垂直留 160 px；每個 Section 內 Frames 依末段數字由左到右排列，Frame 間水平留 80 px。超出畫布時維持同一 Section 的數字次序換行，行距 80 px；下一 Section 從上一 Section 最低 Frame 下方 160 px 開始。間距只用於占位排列，不主張產品版面。
- 若 Frame 情境有按鈕處理中／載入文字，在情境標註該狀態即可，不另建按鈕載入 Frame；載入樣式屬後續元件設計。
