- **同意後的系統訊息是 App 端送的，不是後端**（`lib/backend/chatroom/chatroom.dart` 的 `replyTimeRequest`：`confirm == 1` 時，用 `sendText` 送出一般文字訊息「【系統訊息】施工時間更改至yyyy年MM月dd日，HH:mm」，日期後是全形逗號、24 小時制）。所以它是同意的那一方送出的普通訊息：師傅按確認，就是師傅自己的黃底氣泡（5.1.9）；客戶按確認，師傅看到的是白底氣泡（5.1.8）。拒絕時不會送。先前我只查後端，漏看 App 端，已更正。

- `DatePickerPanel`（放在本 Page 右側「本機元件」Section）：TEXT 屬性 Month。內容為日曆（月份標題、星期列、5 排日期）與時間滾輪列。

只記例外：

- **5.1.1 頂部多一條可關閉的粉紅提醒**（程式 `CloseableCard`，「📢 聊天室不談報價金額，請客戶詢問平台客服」，左右 8、下 8）：DS `Banner`（Tone=Error、Solid=false、Leading=None、Closable 開），放在 ChatAppBar 與 `Content` 之間，是固定區，不隨訊息捲動。字級與圖示照 DS，程式是 16 Medium。
- **對話最上方的「師虎提醒您…」說明**（程式 `topInsert`，14 灰，左右 32）：`Body/S`＋`Text/Hint`，放在 `Scroll Content` 第一項（`Colors.grey` #9E9E9E 沒有同值文字 token，選 `Text/Hint`）。訊息多到超出一屏時它會被捲出畫面，示意資料故意只放 5 則，讓它看得到。
- **標題「與 王先生 對話」**：ChatAppBar（To Client），姓名放在底色框（程式 `obscureName`，後端格式為姓氏加先生／小姐，與 2.2.1 同一位客戶）。
- **訊息種類**：對方文字、自己的通話紀錄（後端文字為通話時長「02:35」，另有「取消」「無回應」）、日期分隔，以及約施工時間請求。約施工時間的請求（程式 `TimeRequestMessage`，自己送出的是黃底一般氣泡，文字「請問 2026年10月09日, 10:00 ，可以與您約定施工時間嗎?」，日期格式 `yyyy年MM月dd日, HH:mm`）用 MessageBubble Text Self 版。
- **約施工時間的回應流程（後端 `TimeRequestReply.ts`、`ChatroomService.replyTimeRequest` 查證）**：師傅送出的請求文字是 `0@日期`，原訊息不會改。對方按確認或取消後，後端會**新增一則**回覆訊息（`1@日期` 或 `-1@日期`），由回覆的人送出，確認時同時更新訂單的預計施工日期。所以師傅端有三種畫面：自己送出的請求（黃底，已畫在 5.1.1）、客戶回覆的「同意更改施工時間至 …」「拒絕更改施工時間至 …」（對方白底氣泡）、收到客戶送來的請求（白底氣泡加「取消」「確認」兩顆文字鍵，兩邊都能發起，客戶端 `to_master_chatroom.dart` 也傳了 `onSendTimeRequest`）；師傅按下後自己的回覆是黃底氣泡。**先前我寫「同一則訊息文字會變」是錯的，已更正。**這幾種狀態結構表沒有獨立 Frame，等使用者決定編號。
- 5.1.2 複製 5.1.1，輸入列換成 Expanded（TimeRequest 開）：同時有「傳送照片」「約施工時間」。為了展開後內容區縮短 64 時最後一則訊息不被切到，示意訊息都縮成一行。
- **5.1.7 日期選擇面板（新畫面類型，使用者已確認）**：DS 沒有日曆與時間滾輪，搜尋過 date、calendar、picker、wheel、time 都沒有結果，整塊自排。BottomSheet（hasHeader、無取消與底部按鈕、高 596＝852×0.7），標題置中，右側「完成」是把標題列的 IconButton `swapComponent` 成 Button Ghost Action sm。日曆是 Material `CalendarDatePicker`：月份標題加下拉箭頭、上下月箭頭（上個月停用，因為可選範圍從今天起）、七欄 42 高的週列與日期列；今天（10/07）是選取狀態，藍框圓圈加藍字，今天以前停用（灰字，用 `Text/Hint`，無停用色 token）。時間列是「時間」標籤加三欄滾輪（上午／下午、時、分，分鐘間隔 30），中間選取條 `Border/Default`，上下鄰近項灰字被 70 高的區域裁切。
