# D01 現況服務流程表（註冊到保固）

## 概述

師虎來了現況的訂單流程，從註冊到保固，是 D01 流程圖的底稿。內容整理自 wiki 的[訂單生命週期](../../../../wiki/process/order-lifecycle.md)與各階段流程文件，圖定案前先在這張表確認。

本表只寫現況，不寫 D02 接點。人工處理的例外情境（師傅遲到爽約、跳過場勘、報價有誤、不同意驗收）不上圖，細節見各階段流程文件。

名詞：
- 圖上泳道由上而下：客戶（App）、系統與後台（自動規則加客服人工）、師傅。客戶在 App 上的操作與 App 顯示的畫面放在同一條泳道。表中「App」指畫面顯示或提示的內容。
- 〔人工〕：客服或主管手動執行，圖上用橘色節點表示。
- 〔同意〕〔期限〕〔發票〕：圖上都用節點右上角的小標籤表示。〔同意〕是客戶要明確按下同意的條款。
- 括號內的數字是訂單狀態碼。

## 主幹

| 1a 已有帳號 | 客戶：輸入密碼登入 | | | |

| 1c 其他狀態（旁邊小端點） | 停權：App 畫面變成空白，沒有提示<br>需重設密碼（後台代建）：進入重設密碼頁，設完即可登入 | 後台代建帳號：客服以手機號、姓名、Email 建立，狀態為需重設密碼 | | |

## 主幹旁的小岔路

| 岔路 | 發生在 | 做法 |
|---|---|---|
| 報價攔截（40） | 步驟 8 之後 | 標準報價單且未稅報價 ≥ $50,000，客戶帳號又開啟攔截，才進入。〔人工〕總經理審核，通過進 45，未通過退回師傅重送 |
| 等待支付訂金（50） | 步驟 9 之後 | 施工款 > $50,000，客戶先付三成訂金再進施工。付款成功開立訂金發票 |
| 追加報價 | 步驟 10 施工中 | 師傅提交追加報價單，一次一筆，客戶同意後才可施工 |
| 無尾款直接完成 | 步驟 11 之後 | 派遣費或折讓已全額抵扣，略過步驟 12，直接進 70 |
| 評價與小費 | 步驟 12 之後 | 客戶評價師傅（選填，只顯示一次），之後可給師傅或客服管理師小費（僅限刷卡），付款成功開立小費發票。師傅也可在客戶同意驗收後評價客戶（星數加文字評論，只記錄在後台，不公開） |

## 分支

| 分支 | 發生在 | 做法 |
|---|---|---|
| 配對失敗（95） | 步驟 4 | 媒合截止無人承接，訂單自動關閉。客戶本人或管理員可重啟媒合，回到 10。訂單列表看不到 95 的訂單 |
| 未支付派遣費（97） | 步驟 6 | 逾時未付，訂單取消，記客戶一次「未付派遣費」 |
| 客戶中止媒合 | 步驟 4 | 客戶在狀態 5、10 可按「中止媒合」，記一次取消。已媒合後 App 沒有取消按鈕 |
| 報價被拒（35） | 步驟 9 | 客戶拒絕，退回師傅修改重送，次數不限。談不攏則訂單終止，派遣費不退，師傅約得 $200 |
| 售後服務 | 步驟 14 | 客戶按「我要售後服務」，〔人工〕客服致電、判斷是否屬保固範圍。屬於：聯繫原師傅回場維修，師傅不得收費；不屬於：客服說明原因 |

## 帳號限制（獨立色塊，虛線連到步驟 2、3 與停權端點）

| 限制 | 觸發 | 效果 |
|---|---|---|
| 禁止下單 | 未付派遣費累計 2 次、取消累計 3 次（自動）；客服勾選（人工） | 仍可登入，按「開始叫修」看到彈窗 |
| 禁止接單 | 客服勾選（人工），師傅端沒有自動規則 | 師傅不再被推送案件，按「我要接案」看到提示 |
| 停權 | 客服在後台操作（人工） | 無法登入，App 畫面空白 |
