# 客戶端網頁版下單構想

## 概述

- **類型**：新功能（客戶端新增網頁操作路徑）
- **受影響角色**：客戶、客服、合作企業
- **狀態**：純初步構想，尚未定案
- **來源**：2026-09-23 與董事長討論

---

## 問題定義

### 痛點

- 合作夥伴反映：要客人先下載 App 才能下單會造成斷層，不利於合作導流
- 董事長聽說 Pro360 約一半客戶使用網頁版，建議我們不一定要強制客人下載 App
- 公司現階段策略是與大企業合作帶客人進來，網頁版可降低對方串接與導流的門檻

### 現況

- 客戶無法在官網下單，僅能透過 App 送出需求，官網只提供品牌與服務資訊。見 [產品版圖總覽](../../../wiki/product/product-map.md)、[角色地圖](../../../wiki/product/role-map.md)。
- 師傅端已有網頁版報價單，證明「把 App 功能搬到網頁」的模式已有前例。見 [報價流程](../../../wiki/process/quotation-flow.md)。
- 過去以為「不能做網頁版」是因為需要手機定位。實際上只有師傅端需要手機定位；客戶端是以下單地址配對附近師傅，不需要定位，所以沒有這個限制。

## 設計方向

初步範圍：把客戶端 App 的主要功能搬到網頁。

- 網頁註冊、網頁下單
- 網頁查看訂單進度
- 網頁聊天室
- 後台共用同一套，只是客戶來源不同

網頁版相對 App 的差異：

| 面向 | 說明 |
|---|---|
| 優點 | 免下載、導流不斷層；不需上架審核；由我們自行更新，不會有客戶停在舊版 App |
| 缺點 | 手機上的操作體驗通常不如 App；需額外開發 |
| 開發人力 | 前端網頁工程師即可 |

相關延伸構想（優先級偏後，本探索暫不展開）：延後註冊時機，讓客戶先填完需求與工項再註冊，提高下單完成率。網頁版特別適合搭配這個做法。
