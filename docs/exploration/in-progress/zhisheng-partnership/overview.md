# 智生活合作：專案總覽

## 背景

智生活是合作夥伴，他們的 App 有「到府修繕」入口。公司要把目前提供的修繕服務放進智生活的 App，讓他們的用戶可以下單。初期可能走人工處理（用戶在智生活下單，由我們人工接手），後續若合作延伸，再視需要設計內容或做 App 串接。系統串接的設計見 [B2B2C 串接專案](../b2b2c-integration/overview.md)。

## 目前的工作

| 工作 | 內容 | 狀態 |
|---|---|---|
| [工項照片與說明提供](photo-supply.md) | 董事長指定 14 小項的照片、對應工項編號與說明 | 進行中，禮拜五前提供素材 |
| [工項對照表（草稿）](item-table-draft.md) | 以工項為單位（圖片、工項、說明為一組），按 14 小項分組，討論定案後轉 Excel | 討論中 |
| 智生活-師虎來了-工項對照表.xlsx | 由工項對照表草稿產出的 Excel，含縮圖，前兩欄相同文字已合併儲存格；草稿有更動時需重新產出 | 已產出第一版 |
| [保固說明（供貼上）](warranty-text.md) | 董事長上架版 Excel 的保固說明欄，19 個項次，內容照平台原文，由專案負責人複製貼到她的表格 | 已產出，待董事長確認 |
| 圖檔/ | 依董事長上架版 Excel 的項次整理 19 張原始照片，每個項次一張，檔名照她的項次與工項名稱 | 已整理，待上傳到共用資料夾的「圖檔」 |

之後有新的合作題目，就在這個資料夾新增文件，並加進上表。

## 已知限制

- 智生活的分類只有一層，我們的 App 有三層（L1、L2、L3），需要配合他們的結構。

## 待釐清

1. 初期人工處理的流程：訂單怎麼從智生活進到我們、誰接手、怎麼回報。
2. 商業條件：分潤、客戶歸屬、客服窗口目前沒有資訊。
3. 後續是否做 App 串接，以及時程與範圍。
